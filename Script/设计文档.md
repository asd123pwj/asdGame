# 项目共通设计文档

> 本文档汇总本项目各脚本共通的**设计思路与编码规范**，供后续开发与 AI 参考。UI 文件夹有独立 `Script/UI/UI.md`。

## 一、命名规范

- 类名：`extends BaseClass`（几乎一切自定义类都继承它，获得唯一 `ID`）。`class_name` 用有语义的名，多词大驼峰。
- **全局注册的单例/系统**用短名 `Sys` 前缀别名：`Sys.sysCfg / timeSys / charSys / inputSys / tmapSys / cmdSys / uiSys / pointDetect`（见 SystemManager，`static var` 指向实例）。
- **指令/命令类**：宿主为继承 BaseClass 的静态类，命令名 = `类名.方法名`。
- 带前缀的约定：
  - Preset 配置类：**本文件不强制前缀**，但实例化名多为 `XXXPreset`；配置数据放 `Config/` 同名（见三）。
  - UI 自定义元素：`UI_` 前缀 → type 去掉 `UI_`。
  - 各系统静态集合管理常用复数名：`Attributes/Statuses/Skills/Interactions/Collisions/Inventories/SystemShortcuts`。
- **一律显式写类型**（含 Dictionary/Array 第二层），**不用 `:=`**（Godot 无法推断复合类型第二级，易 unsafe 警告）。示例：`var d: Dictionary = {}`、`var list: Array = []`。对字面量也要标注：`static var _we: Dictionary = {}`。
- `extends BaseClass` 的类，静态成员表惯用 `static var _we`（字典，name→实例）。
- 私有方法/字段前缀 `_`；静态常量用大写或直接 `static var`。
- 消息 ID 用字符串常量（如 `TimeSys.msgID_advance`）或 `Msg` 门面按需 `_format_xxx` 拼。

## 二、目录组织与一个功能的写法

每个"有配置 + 有行为"的功能，遵循**统一分层**（参考 Character 系统）：

1. **Preset 配置类**（放 `Script/<域>/`，`extends PresetRegister`）：定义"一条配置长什么样"，`.gd` 内常含 `_init` + `static get_(name)`，从 `Config/<域>/` 读同名配置并注册进 `static _we`。
2. **集合/管理类**（放 `Script/<域>/`，每角色一份或静态）：按 `_init(me, name数组)` 把预设"装到角色身上/注册"，暴露 `add_/remove_/check_`。
3. **XXBase + 具体实现**（`Script/<域>/XXXs/` 子目录）：Base 抽通用，子类覆写开放接口。
4. **Config/<域> 配置文件**（`extends ConfigBase`）：`values: Array[Dictionary]`，每个 Dictionary 一条配置记录，批量喂给对应 Preset。支持用户目录 json 覆盖。

## 三、PresetRegister 与 ConfigBase 的配合

**PresetRegister**（`Script/Utils/PresetRegister.gd`）：一个"注册/装载"基类。
- `extends PresetRegister` 的**配置子类**（如 `Archetype_Basic`）在 `extends ConfigBase` 里声明 `values: Array[Dictionary]`，每条是一 Dictionary。
- 用法：`Sys.presets = PresetRegister.new()` 时，`PresetRegister` 扫描 `Config/` 下所有继承自己的配置类（`get_global_class_list` 找 base==自己），逐个实例化它们的 Preset 描述。
- 因此"要加一个新预设" = 在 `Config/<域>/` 加一个 `extends ConfigBase` 的类，`values` 填 Dictionary；**无需改运行代码**。

**ConfigBase**（`Script/Utils/ConfigBase.gd`）：
- 子类声明 `values: Array[Dictionary]` + 其他字段。
- `_init`：若无用户配置则把 `values` 存成默认 json；用户可改 `user://Config/` 同名 json 覆盖（`Sys.USER_CONFIG_DIR`）。`RESET=true` 时每次重置默认。
- 提供 `_assign_property` 按字段名给对象赋值、`script.get_global_name()` 定位自身等。

**配置文件名命名**：`Config/<域>/<Preset类型>_<批次>.gd`（如 `Archetype_Basic.gd`）。文件内 `values` 数组即该类型的若干条配置。

## 四、参数设计（可变参数 / 全局值放哪）

- **项目级可调参数**：放 `SysCfg`（`Sys.sysCfg`，如 `random_seed/hour_period/damping 阈值/分帧周期`），运行时改 `SysCfg` 即生效。`SysCfg` 在 `Config/SystemConfig.gd`，`Sys.sysCfg = SysCfg.new()`。
- **某条配置内参数**：放进该 Preset 的 Dictionary（`Config/` 下），如 Skill config 的走速/阻尼系数。
- **静态常量值**：直接用 `static var` 字面量，或 `static const`（Godot 中不可变类型）。
- **引用另一属性/动态值**：在指令/配置里用表达式（见五）。
- 规则：**全局/系统级**→SysCfg；**单条实例级**→Preset 的 config；**代码常量**→static。

## 五、表达式 / 取值（CommandParser）

命令参数值或配置里可用 `$`/`&` 取值表达式（静态 & 实例）：
- `$Test.xxx` / `&Test.xxx`：读静态成员值。
- `$@实例ID.属性[下标].xxx`：读实例成员（`instance_from_id`），链式 `.key`/`[数字]`，遇 `()` 调方法。
- `$Test.func(...)`：调静态/实例函数。
- 详见 `Command/` 总结与 CommandParser 注释。

## 六、消息总线（Msg）解耦

- 几乎所有跨模块联动走 **`Msg`**（`Script/Message/MessageHub.gd`，`class_name Msg`，集中了全部 send_/listen_/get_ 静态方法）。
- 底层 `MsgBus.send(id, msg)` → 广播给该 id 的所有 receiver，**返回各 receiver 返回值数组**；`listen` 存 Callable，`unlisten` 移除，无人听时消息节点自动清。
- **消息 id 约定**：通用事件用字符串（`"CHAR_CREATE"/"COMMAND"/"TIME_ADVANCE_*"`）；角色级事件用 `format_ID(["CHAR", ID, type, type_name, action])` 区分到"具体角色的具体某类事件"，由此"监听某个角色的某状态/某技能/某碰撞"变得精确。
- **标准配套**：`send_xxx` / `listen_xxx` /（部分）`get_xxx`(读最近一次 message)。key 类消息区分 `DOWN/FIRST_DOWN/FIRST_UP`。
- 返回处理：`send_cmd0` 取 `[0]`、`send_cmd00` 取 `[0][0]`（剥离接收者外层）。

## 七、有变种的 XXBase 如何写

当"同一抽象有多个具体行为"（如 Skill_Walk/Gravity/Jump、Interaction_Attack/Heal...）：
1. 建 `XXBase`：存公共状态(如 config/name)、提供通用工具方法（如 InteractionBase 的 attack/heal/cost/impact），并声明一个**虚接口**（SkillBase._act / InteractionBase.interact）默认报错或空。
2. 各具体 `XX_xxx`：`extends XXBase`，只覆写该接口，其它全部继承。（若某抽象无需行为实现、只需"状态满足→执行一条指令"，可用更轻的 `SystemShortcut`，见 `Character/SystemShortcut/SystemShortcut.md`。）
3. Preset 通过一个"实现类名"字段(如 `interaction_name`/`skill_name`)实例化对应实现：`_init` 里按名 new 并缓存到 `_we`。
4. 需要被自动发现时，让 XXBase `extends` 标记基类（如 CmdSource），或用文件名/类名前缀约定，`register`/扫描时找其子类。

## 八、一帧驱动（每帧/物理帧入口）

- `Sys`(extends Node) 的 `_input/_process/_physics_process` 是唯一引擎回调入口，各自转发给对应静态系统：
  - `_input`→`InputSys._input`
  - `_process`→`InputSys._process`、`TimeSys._process`
  - `_physics_process`→`CharSys._physics_process`（再驱动各 Character 的 skills 等）
- 系统若想每帧被驱动，做成**静态 `_process(delta)`**，在 `Sys` 回调里调用即可；不用靠自身继承 Node 收 `_process`。

## 九、常见给后续参考的要点

- 一切自定义对象几乎都 `extends BaseClass`，天然带唯一 `ID`（`get_instance_id()`）。
- 需要"改这份配置即可新增功能，不改代码"→ 用 ConfigBase.values + PresetRegister。
- 需要"按名查已注册实例" → 对应类的 `static _we[name]` + `static get_(name)`。
- UI 自定义元素/命令宿主等"按类型名自动实例化" → 用 `ProjectSettings.get_global_class_list()` 按 `class_name` 或基类名匹配并 `new`，结果可静态缓存。
- **UI 系统同样遵循本范式**：`UIPreset`(PresetRegister) + `UiSystem`(管理脚本) + `UIBase`(包装 Control) + `Config/UI/UIPreset_*.gd`(ConfigBase)；详见 `Script/UI/UI.md`。
- **Archetype 元素可内联或引用**：archetype 各模块数组的元素，既可写"预设名"(字符串，引用别处已定义的配置)，也可直接写该预设的"内联配置"(字典/列表)。内联时按字段对应的类现场创建并注册(字典取 `name`、列表取首参)，重名则 `push_error`。由此"只在一处出现"的模块(如系统专用状态/快捷)可内联进 archetype，无需另建配置文件。字段→类映射见 `Archetype._field_class`。
- **引擎对象按需生成、可为空**：包装的引擎对象不必在构造时立即创建。如 `Character.body` 由 `ensure_body()` 延后创建（在各"需要点"如进入世界 `CharSys.spawn`、技能驱动 `Skills.physics_process` 时创建；body 生成时会顺带补挂已装碰撞区 `collisions.attach_collisions()`），`Archetype.bodies` 为空的角色则留空 `null`——由此可做"无 body/碰撞的纯逻辑角色"(如持有按键状态的 sys 角色)。依赖 body 的部件（如碰撞区）在无 body 时应直接跳过，待 body 生成后再补建，而非强行触发 body 生成。

## 十、包装引擎对象（不直接继承引擎类）

当需要一个"自定义对象"去驱动一个 Godot 引擎对象（Control/Node/Area2D...）时，**不要**让自定义类直接 `extends` 该引擎类，而是：

1. 自定义类 `extends BaseClass`（获得唯一 `ID`、参与 Preset/消息体系）。
2. 类内用一个变量**持有**引擎对象，如 `var control: Control`，由该类的 `build()/create()` 生成并返回（参考 `BodyPreset.create() -> CharacterBody2D`）。
3. **对外交互一律走 `Msg` 消息**（在 `MessageHub.gd` 补 `send_ui_xxx` / `listen_ui_xxx`），**不要**用自定义 `signal`。输入也**不直接用引擎 `gui_input`**：指针类输入统一由 `PointDetect` 用 `InputSys` 检测命中后回调本对象（如 UI 的 `on_pointer_down/move/up/on_submit`），只有控件自身的引擎内建信号（如 `Button.pressed`）保留。
4. 配置与注册仍走 Preset（`UIPreset extends PresetRegister`）+ `Config/UI/` 配置类（`values: Array[Array]`，每条为 `_init` 的位置参数）。
