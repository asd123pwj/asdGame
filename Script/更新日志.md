# 更新日志

## 0.26.12 键盘UI

- 把之前在Unity写的键盘UI迁移过来了，用于快捷绑定按钮，参考的冒险岛的快捷键绑定界面
  - 没有什么特别的，只是UI的组装，以及组装时进行了纠错和补充

### 新增 · 键盘快捷键界面（Config/UI/UIPreset_Keyboard.gd）

- **一份配置 = 整个界面**：`values` 里只有一个 `Keyboard`（`UI_Panel`），103 个键由文件里的 `KEYS` 表**在 values 外算好**再由 values 引用（`_layout`）。
- `KEYS` 每列是 **[键码, x, 行, 尺寸, 显示文本]**（左右修饰键多一列 `KEY_LOCATION_LEFT/RIGHT`）：
  - 数值照抄 Unity 那版的原表达式（`32*2`、`row1 = -36*2`…），统一再乘一个 `SCALE`；**表里保持 Unity 原值，要缩放只改 `SCALE`**。当前 `SCALE = 1.0`（= 与 Unity 同尺寸：面板 1600×576、键 64×64）。
  - **键码才是这个键的身份**（`KEY_ESCAPE` / `KEY_Q` / `KEY_KP_8`…），最后一列只是给人看的文本（"Esc"、"Space"）。以后"点某个键 → 绑到某操作"就是拿 `config["key_code"]`（+ `key_location`）造 `InputEventKey`。
  - 左右 Shift/Ctrl/Alt 在 Godot 里 **keycode 相同**，靠 `InputEventKey.location` 区分 → 这三对多一列位置，**元素名也带 `_L`/`_R`**（不带后缀两个键会注册到同一个名字下互相覆盖）。
  - 元素名由键码字符串生成（Godot 自带的名字很好用）：`Escape→Key_Escape`、`Q→Key_Q`、`Kp 8→Key_Kp8`、`Slash→Key_Slash`、`Shift+LEFT→Key_Shift_L`；生成时做重名检查并 `push_warning`。
- 每个键 = 一个 `free` 的 `UI_Panel`（绝对坐标定位，底图 `KEY_BG`，配置里带 `key_code` / `key_location`）+ 两个 `UI_Label`：`Name` 键名、`Desc` 当前绑定的操作（默认"占位符"）。
- 整块面板按住可拖动（`"Mouse Left | Tick"` → `drag $self`，与 MiniHUD 标题栏同一套）。
- **核对过 Unity 原型**（写脚本逐项 diff 位置/尺寸/短名）：103/103 完全一致；键位极值 `right=1578 / bottom=504` 对面板 1600×576（左右各 22、上下各 72，完全对称）⇒ 位置基准是**键的左上角**（Unity 的 `anchoredPosition` 不是中心，两条独立证据：极值自洽 + 键内 `UIKeyName` 的 `new(6, -8)` 偏移）。
  - 唯一差异：Unity 的 `"Backpack"` 按笔误处理成了 `"Backspace"`（要还原说一声）。
- 开启：独立 UI，`UIInteract.open_ui --preset_name Keyboard` + 右上角的 `CloseButton`（普通预设，见 `UIPreset_Basic`）——见 `Test.ui_test`。

### 通用化 · 三个配置项从"某元素独有"提到 UIBase

- `font_size`（原来只在 `UI_Label`）、`font_color`（新增）、`background`（原来只在 `UI_Panel`）现在都在 `UIBase._apply_config` 里读：
  - `font_size` / `font_color`：**主题重写不向下传**（实测：根上配 11，子 label 读到的是默认 16）→ 要小字/深色，必须配在**真正显示文本的那个元素**上。
  - `background`：虚接口 `_apply_background` + `_background_slot`（按 `panel → normal → background` 取第一个存在的槽）+ `_make_background`（九宫格，边距取 `background_slice`，默认 `BG_SLICE = 8`）。
  - `UI_Panel` 覆写 `_apply_background`：底必须套在**内层 PanelContainer** 上（它的根 Control 是普通 Control，自己不画 StyleBox）。
- **实测各元素能用的槽**（`Theme.has_stylebox`）：

  | 元素 | 内部控件 | 槽 |
  |---|---|---|
  | `UI_Panel` | PanelContainer | `panel` |
  | `UI_Label` | Label | `normal` |
  | `UI_Scroll` | ScrollContainer | `panel` |
  | `UI_Image` | TextureRect | 无（配了只警告一次、不画） |

- 顺带记录两个实测差异（结论：**不能拿"空 Label"当 `UI_Image` 用**）：
  - 空 Label + 底框最小尺寸 `(1, 23)`（按字体行高算），`UI_Image`（`EXPAND_IGNORE_SIZE`）是 `(0, 0)`。
  - `UI_Image` 的 `content` **就是那张图**（`set_content(路径)` 换图）；`UI_Label` 的图只能当 `background`（换图 ≠ 改 content），缩放语义也不同（StyleBoxTexture 是九宫格=框，TextureRect 有 `stretch_mode`/`expand_mode`=自由缩放）。

### 修正 · 配置子元素不认 `free`（键盘 103 个键被排成一列）

- 现象：键的 `transform.size` 全被拉成 `(1088, 45)`，一列铺满、顶到边。
- 原因：`UIBase._build_children` 无论有没有 `free` 都往 `_content_box()`（VBox）里塞；`free` 的绝对定位逻辑只写在运行时的 `add_child_element` 里 —— 又是"同一需求两套策略"。
- 修法：两条路共用一条规则（`free` → `_free_box()` 叠加层，位置/尺寸不被布局改；否则 → `_content_box()` 竖排）。之前菜单、`CloseButton` 用的是运行时那条路，所以没暴露。
- 顺带给 `UI_Panel` 的内部节点起名（`Panel` / `Margin` / `Box` / `Overlay`），编辑器里看树不再是 `@Control@35`。

### 说明 · 键里"看不见字"

- 探针实测：文本、字号、位置全对，但**字色是主题默认的近白色 `(1,1,1,1)`**，画在浅色键底上等于隐形。
- 结论：**配浅色底图时必须显式给 `font_color`**（键盘现在给的是 `Color(0.13, 0.13, 0.16)`）。

### 验证

- 探针实测（跑完即删）：键的 `size`/`position`/`min`、`key_code`/`key_location`、字色、元素名（含 `_L`/`_R`）、`UI_Scroll`/`UI_Label` 的 `background` 槽与套用结果。
- 复跑（`--headless --quit-after`）无脚本错误、无警告。
- lint：改动文件干净（`PointerDetect` 的 3 条 `shape` 警告、`test.gd` 的 `Variant.keys()` 是既有的）。
- 编辑器 LSP 偶发旧索引假报错（如 `"_make_background()" not found in base self`）：无头跑里同一调用是成功的，点状态栏 Retry 即可。

### 注意

- `SCALE = 1.0`（与 Unity 同尺寸）时面板是 **1600×576**，比默认窗口 1152×648 大 —— 窗口不够大就把它调小，或把 `PANEL_POSITION` 按窗口调（字号不跟着 `SCALE` 走，改完自己看着调）。
- 旧 json 仍是老问题：`Archetype_System.json` / `UIPreset_Basic.json` / `UIPreset_Menu.json` / `UIPreset_Keyboard.json` 会覆盖代码里的 `values`；当前 `Sys.RESET = true`（每次启动重新写盘、不读旧 json），不需要手动清理。
- 加"开关/状态"的固定套路：两套配置写在同一个元素上 + `swap_config` 对调；给某个 UI 加/减东西：开/关一个预设 UI（`open_ui` / `close_ui`）。
