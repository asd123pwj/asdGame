# 更新日志

## 0.26.5 指令缓存

- 指令系统在未来应该是一个负载极高的系统，它可以很方便在外部对任意方法/属性进行访问
- 因此，实现指令系统的缓存。
- 缓存有两级，新指令进来移到队头，已存在的指令进来同样到对头，满了后队尾的指令移到二级缓存
- 二级缓存按时间清理，时间按桶分配，一次清理一个时间段对应的桶，减少遍历次数

### 新增 · 指令"编译/执行"两段式与两级解析缓存
- 说明：指令的解析拆为"编译计划(含 `$`/`&` 表达式的定位) + 执行计划(实时取值)"两段。计划按命令原文缓存：**L1 热缓存**(LRU 双向链表) + **L2 温缓存**("时钟指针 + 时间桶"实现 O(1) 过期与淘汰)；可用 `SysCfg.cache_command` 一键关停。

### 修改
- `Script/Command/CommandParser.gd`：重写为"编译/执行"两段式——`_compile` 固化确定性部分（分词、字面量、`$`/`&` 定位），`_run_plan`/`_run_expr`/`_run_ops` 只做最后一步实时取值；`$` 表达式编译成计划（`func`/`member`/`instance`/`literal`）；新增 L1(LRU 双向链表) + L2(时钟指针 + 时间桶，`_l2_ring`/`_l2_hand`/`_l2_index`)两级缓存与 `clear_cache()`；删除被取代的旧求值器与线性扫描清理（`_eval_expr`/`_resolve_instance`/`_walk_chain`/`_eval_arg`/`_try_resolve_member`/`_apply_accessors`/`_trim_l2` 等）。
- `Script/Command/CommandParser.gd`：修复 64 位实例 ID 解析——`is_valid_int()` 按 int32 校验、且 `-1` 无效哨兵会与负数 ID 冲突，`_chain_id` 改为返回 `[ok, id]` 并允许前导负号；`_convert_literal` 的整数字面量改用 64 位判定；`[n]` 下标支持负号并校验闭合；`_run_arg` 兼容"无值 flag(bool)"不再崩。
- `Script/Command/CommandSystem.gd`：移除 `_exec_cache`（与 Parser 缓存重复且无界），`execute` 只做"查命令 + 组装参数 + 调用"；`clear_cache()` 改为级联清 Parser；修正文件头 `&` 取值语法的注释笔误。
- `Config/SystemConfig.gd`：新增 `cache_command`(总开关)、`cache_command_l1_capacity`(默认 256)、`cache_command_l2_ttl`(默认 300s)、`cache_command_l2_period`(轮转周期，默认 1s)、`cache_command_max`(L2 总量上限，默认 1024*1024)。
- `Script/Command/Command.md`：改写为"编译/执行两段式 + 两级缓存(时间桶) + O(1) 过期"说明。
