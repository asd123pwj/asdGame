### 更新内容

- **新增：角色技能查看 UI**（`Config/UI/UIPreset_Skill.gd` + `Script/UI/UI/UI_Skill.gd`）
  - 打开：`UIInteract.open(preset_name="Skill")`，默认看 `char_A`（换人写 `content_cmd="@Char/兔子"`，再点 `[刷新]`）
  - **一条技能 = 一段**（默认收起，标题是摘要
    `名字（实现类 ｜ 依赖：状态名 ✔ ｜ 在队列 ｜ 最近执行 17:58:46）`），展开看五类信息：
    `skill_name` → 实现类（类名写错时红字报"**没建出来**"）／`dependence_status` → 依赖状态 + 现在满不满足
    （带 `@identity` 的连"解析到了谁"一起写，技能表里本来就这么写：`Right@SYS`）／**队列**（在不在 + 队列里那份参数）／
    **流水三行**／`config`（技能的参数是数组，一行说清，如 `[300]`）
  - 实时：每条技能订**它依赖的那个状态**（`satisfied` / `unsatisfied`——与 `SkillPreset.listen` 进 / 出队看的是同一个节点）
    ⇒ 只重铺那一段，"在队列 / ✔✘"当场变；另订"任意技能"通配（见下）
- **新增 `ANY_SKILL` 通配**（`MessageHub`）：`send_skill_any_changed` / `listen_skill_any_changed`
  - 节点 `["CHAR", 角色, "ANY_SKILL", "ANY", "changed"]`、payload `[预设名, 动作]`；三个具体的 `send_skill_*`
    各顺手发一条 ⇒ "不关心是哪条技能"的订阅**订一条就够**（具体消息按预设名分节点，运行期新加的技能本来收不到）
  - **`act` 是每物理帧都发的**（技能逐帧执行，**消息不省**）⇒ 订它的一方要自己扛住这个频率：
    一览那边不重铺，只把段标题那一行"最近执行"就地换掉（`_on_act`；**文本没变就不刷**——省掉的是绘制）
- **动作流水抽成一份 `ActionHistory`**（`Script/Character/ActionHistory.gd`）
  - 上一版交互那套（`clock` 现实墙上时钟 + `text` 游戏时间）搬成独立类，
    **交互与技能各持一份实例**（`Interactions.history` / `Skills.history`），实现只有一处：
    `record(key, action)` / `get_rec(key)`；**移除也留档**、**先记再广播**这些规矩一起搬过去
  - **限流就在这一个类里**（别在调用方各写一遍）：某个动作在 `SysCfg.history_window` 秒内超过
    `SysCfg.history_window_max` 次之后，**每秒只记第一次**；一直这么算到它安静 `history_window` 秒才复位计数
    ⇒ 稳定的高频动作 = 每秒恰好一笔
  - **限流只管流水这一处，消息照发**：别拿"要不要发消息"当限流手段（那会把别的订阅方一起坑了）；
    界面那边靠"显示的文本没变就不刷"自然省下绘制（流水到秒 ⇒ 一秒最多画一次）。消息本身真成瓶颈再单独优化消息
  - 时间**都到秒**：`clock` = 墙上时钟 `14:03:21`、`text` = 游戏时间 `元年正月初一 子时`；**计数（`act_count`）整个去掉**
  - 技能侧：`add_skill` / `remove_skill` 各记一笔；**执行**那笔在 `SkillBase.act` 里（`_act` 成功才算，随后照常广播）
  - 为此给实现类补了"预设名"：队列的键是 `SkillBase` 实例（认不出预设名）⇒ `SkillPreset._get_skill_by_name`
    建完就写 `skill.preset_name = name`，`act` 用它记流水、也用它广播
  - **修：`send_skill_act` 的 payload 从类名改成预设名**（全项目无人监听旧值，改安全；改完技能域里
    add / remove / act 三个动作的"技能名"口径一致）
- **合并：一览之间逐字相同的零件挪进底座 `UI_View`**（技能一览本来会与交互一览重复的那几个）
  - `_stamp`（一笔流水怎么显示：`17:58:46（元年正月初一 子时）`）、
    `_dep_of` / `_dep_hit` / `_resolve_note`（`状态名@identity` 的解析 / 满不满足 / "解析到了谁"）、
    `_config_rows`（参数那几行：字典一行一键，数组等一行说清）
  - `UIInteract_Fold.title_texts` 因为"就地换标题"又有了真实用处（`content` / `content_2` 两套要一起改，
    不然下次点收起 / 展开会换出旧文字），箭头格式只剩一处定义
- **顺带**：`ui_test` 多开一个技能一览；`Skill.md`（流水 / 预设名 / 一览入口，并修掉"`physics_process` 先 `ensure_body()`"
  那句与代码不符的描述）、`Interaction.md`（history 改成 `ActionHistory`）、`UI.md`（五个一览共用 `UI_View`）、
  `Message.md`（通配那节列全四个 `ANY_*`，并注明 `SKILL` 的 act 每帧都发）、`Character.md`（同上一句）
- 验证：探针实测——6 条技能 / 队列里 3 条照实读出；发 `unsatisfied` 让它出队 ⇒ "在队列=false"且那一段重铺；
  交互一览在这次重构后照旧（段在、流水读得到）；**限流**：同一秒里连记 15 次 ⇒ 记上 10 / 丢掉 5，
  过一秒再连记 5 次 ⇒ 只记 1，安静 5 秒后再记 ⇒ 又记上了（计数复位）；记下的 `clock` 是 `20:31:08`（到秒）、
  两边都查不到 `act_count`；**消息不省**：五个物理帧里收到 4 条 `act` 消息，同期流水只写了一笔；
  `--headless --editor` 全项目解析 clean、`--headless` 跑起来无脚本错误
