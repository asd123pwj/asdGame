## 0.26.22 角色状态查看UI
- 能实时查看角色状态及其依赖情况的UI
- 为了减少不必要损耗，在UI关闭时会自动销毁监听事件
- 至于优化的事情之后再说吧，编辑器UI那里卡了好久。

### 更新内容
- 一个能"看着状态系统跑"的界面：**角色状态一览**（外壳 `Config/UI/UIPreset_Status.gd` + 内容元素 `Script/UI/UI/UI_Status.gd`）
  - 打开：`UIInteract.open(preset_name="Status")`（默认看系统角色 `@Char/SYS`）；换人：开的时候写 `content_cmd="@Char/人类"` 再点 `[刷新]`
  - 每个状态一段、**默认收起**；标题就写着 `✔ 满足 / ✘ 未满足 ｜ 依赖 N 条`，展开才看六组依赖逐条"声明 → ✔ 已触发 / ✘ 未触发"
  - **实时**：状态满足 / 解除时那一段当场重铺（标题的 ✔/✘ 跟着变），而且**段的位置不动**
  - **开着才监听**：面板开着就订上被看角色的所有状态消息，关掉就全退（不留订阅挂在消息系统里），重开自动订回来
- UI 元素多了一对通用的**生命周期钩子**：`on_shown` / `on_hidden`（`UIBase`，`open` / `close` 时递归通知整棵子树）
- 字号加了**默认字号（同时也是最小字号）**：`SysCfg.ui_font_size_default = 16` —— 没配就用它，配得比它小也抬到它（"小到看不清"堵死）
- `UIInteract.open` 去掉了 `content_cmd` 参数：它本来就是个配置键，照「任意配置键」的写法直接写 `content_cmd="…"` 即可
- 修掉的问题：独立 UI 再 `open` 一次会**重建**而不是复用（拼的登记名和登记时用的 `UI/预设名` 对不上）；
  "只重铺其中一块"会把它**排到最底下**；摘子树只 `queue_free` 导致本帧还占位、还会多画一次；
  状态依赖那行原来是 `—`（看不明白），改成 `✔ 已触发 / ✘ 未触发`


- **`UI_Status`（只读 + 实时）**：状态是**静态预设**（一个状态全项目一份：`_x_listeners` 是声明，
  `_x_triggers` / `satisfied` / `latest_message` 是**按角色**存的）⇒ **声明从预设读、现状一律取那个角色的那一份**
  （`preset._attr_triggers[char_]`）；只读预设会把所有角色混在一起。看谁：`content_cmd`（优先）→ 自己的 `char` → 都没有就铺红字。
- **监听生命周期**：订阅每个状态的 `satisfied` / `unsatisfied`，收到只 `replace_child_element` 重铺那一段；
  **开着就全订**（收起的段标题也写着 ✔/✘，照样要实时值）、**关掉就全退**（`on_hidden`），**重开由 `on_shown` 订回来**。
  判断"开着没开"用显式标记（`on_shown` / `on_hidden` 维护）而不是控件可见性——整块收起时子元素是隐藏的，而"隐藏"≠"关掉"。
  回调一律用 lambda（**不用 `Callable.bind`**：`Callable` 的 `==` 不比较绑定参数，退订时摘不掉——同 `AutoSys._index_of` 记的坑）。
- **`UIBase` 的"删 / 换子元素"收成一处**：`clear_children()` / `remove_child_element(ui)` / `replace_child_element(old, 名, 类, 配置)`
  （递归摘注册名 → **立刻脱离控件树** → `queue_free`）；`UI_Editor._remove_tree` 删掉、改调它们。
  **只重铺其中一块要用"原地换"**：摘掉再加会把它排到最底下（`children` 与容器位次都到末尾）——"状态一变那行就跳到最后"就是这么来的。
- **`on_shown` / `on_hidden`**：`UIInteract.open`（`_place` 之后）与 `close` 各 `dispatch_*` 一次，**递归整棵子树**（先自己后子元素）——
  因为"重开一个已存在的 UI"是**复用 + 显示、不发消息**，只靠 `listen_ui_close` 那种消息盖不到这一半。
- 验证：`--headless --editor` 全项目解析 clean；`--headless` 跑起来无 warning。
  探针实测：SYS 16 个状态 / 开着 32 条订阅 ⇄ 关掉 0 条、重开 32 条；收起段收到 satisfied 时标题当场变而**位次不变**；
  字号 没配→16、配 8→16、配 28→28；`content_cmd` 改走 config 后照样生效。


## 0.26.21 实例ID改注册名

- 没什么特别的，实例ID去掉了，之前一串数字，只有系统内部认得出，现在统一改为可读的注册名了。

### 更新内容

- 角色也走上注册名了：**角色的注册名 = `Char/原型类型`**（`Char/人类`），像 UI 的 `UI/` 一样带自己的根前缀
  - 构造只要**原型名 + 身份**（原来那个"名称"参数去掉了——名字由注册名给）
  - 名字与身份是两回事：**名字**跟着实例（`@Char/人类` 一直指它），**身份**是"现在谁演这个位子"（`CharSys.identities`，可改绑；状态名仍可写 `"状态名@身份"`）
- **实例 ID 彻底退场**：基类里的 `ID` 删掉了，指令 `@数字`、配置里的实例 ID、消息节点用 ID 的地方全改成注册名
- 注册名系统
  - `register` 现在**返回真正用上的名字**（重名让路由一个开关管：`dedup`）——角色同名自动排到 `Char/人类_2`
  - 让路算号改成**占名计数表**，不再遍历所有登记名（注册对象只会越来越多，遍历会越跑越慢）
- 验证：Godot 全项目解析 clean；跑起来无 warning（消息节点名、UI 子元素名都照旧）


- **角色**（`Script/Character/Character.gd`、`CharacterSystem.gd`）：`_init(原型, 身份="")`，
  注册名 `Char/原型名`、重名让路加后缀；`_we` 由"ID → 实例"改成"**注册名 → 实例**"，
  `Character.get_("Char/人类")` 按名取（取不到给 null，不再靠 `_we[id]` 直接下标炸）。
- **注册名系统**（`Script/System/RegSystem.gd`）：`register(obj, want, dedup := false) -> String`——返回用上的名字。
  `dedup` 时走 `_claim`：按 `_used_count`（基名 → 已发出去几个）算下一个号，登记表只在"这名字被人手写登记过"时兜底；
  **号只增不减**（名字不回收——回收会让后来者顶着旧名字，而消息节点名是按名字拼的，等于串消息）。
  UI 那条仍走 `unique(want, taken)`：建树时父元素自己还没登记，只能按"已有的兄弟名"判。
- **消息系统**（`MessageHub.gd`）：`_format_character` / `_format_ui` 都用注册名
  （`CHAR->Char/人类->STATUS->Tick->satisfied`、`UI->UI/MiniHUD->open`）；
  指令解析 `CommandParser._instance_of` 只认 `@self` / `@host` / `@注册名`（数字那支删了）。
- **文档**：把 30 处"实例 ID 也认 / 老配置退回 ID / `self.ID`"改准（`设计文档.md`、`UI.md`、`System.md`、各处注释）。
- 验证：探针确认 `Char/人类` / `Char/人类_2` / `Char/兔子_2` 与计数表、消息节点名、UI 子元素名（不该加后缀时没加）、
  "同预设开两次复用同一个 UI 名"都正常；扫描 + 运行 clean。


## 0.26.20 编辑器UI

- 这次写出来的能用，但是代码我不是很满意，感觉通用性有点差
- 实现了一个编辑器UI，能根据数据类型自动扩展编辑项
  - 因为暂时还不确定最终版本，能用就先这样
- 指令系统
  - 增加对字典的支持
  - 当方法参数有`config`时，会将传入的参数中，与函数支持参数不符的部分，视为`config`的键，即简化`config`传参流程
  - 现在`self`, `event`, `host`的前面需要加`@`，减少一些计算量。
- 注册名系统
  - 未来将淘汰`实例ID`，转为注册名，UI的注册名例如`UI/MiniHUD/Title`，使用即`@UI/MiniHUD/Title`，和原先`@实例ID`一致。


- **编辑器只有一种了：`UI_Editor`（自适应）**——把"要看 / 要改的那个东西"铺成可编辑界面，自己按数据类型挑编辑方式：
  字典 ⇒ 一行一键；字典数组 ⇒ 一项一段（**默认收起**，展开才建）；数字 / 真假 / 文本 / 数组 ⇒ 一个合适的控件。
  "编辑哪个东西"由 UI 通用的**查看项**指定（`content_cmd` / `content`；`host.xxx` 是相对写法），不写就是 host 的 config
  ⇒ **右键任意 UI 就能编它**；要编别的东西（另一个 UI、以后某个角色的属性）只是把对象指过去。
  "一行长什么样、用什么控件" = **模板**（`Config/UI/UIPreset_Editor*.gd`），换个模板就是改一处名字（`kinds` / `special`）。
- **查看项有了"指令版本"**：`content_cmd` 优先（显示什么可以随时算出来），`content` 是字面值 / 兜底；
  指令版本生效时字面值存进内部影子键 `_content_static`，撤掉指令版本还能回到它。
- **指令系统三件事**：
  - `@self` / `@host` / `@event` **由指令系统自己解析**（`UIBase` 里那套"扫字符串换占位符"整套删掉）；
  - 注册名加 **`UI/` 根前缀**（`UI/MiniHUD`、`UI/MiniHUD/Menu/Close`），别的系统以后各用自己的根前缀；
  - 支持**字典字面量** `{...}`（可嵌套；参数切分也认 `{}`），以及**「任意配置键」约定**：方法签名里有 `config` 参数时，
    调用里**没对上参数名**的命名参数都进它 ⇒ 打开时顺手改任意一项配置：
    `UIInteract.open(@host, "Editor", @host, host=@host, content_cmd="host.config", size=[300, 200])`。
- **折叠交互变成通用的"按需加载"**：某段声明了 `items` 时**首次展开才建**里面的东西（编辑器每一段都靠它，
  不必再为编辑器写专用的展开函数）；点标题收 / 展那一套片段也从预设挪到折叠交互里（预设只构造自己的 widgets）。
- **注册名系统**（`Script/System/RegSystem.gd`）：注册名 ↔ **实例**（去掉"实例 ID"那一套；要指哪个东西就写名字）。
- **菜单**：编辑器有自己的右键菜单（"编辑这个编辑器 ▸"）；原来"绑定 ▸"（`config["bind"]`）**废弃** ⇒
  菜单编辑 ▸ → **内容对象 ▸** = 开通用编辑器改宿主的 `content_cmd`（不再为"填一个路径"写专门面板）。
- 修掉的问题：编辑器里提交普通文本会**清空**（"文本 → 值"缺了兜底）、相对写法 `host.` 没展开（编辑器只剩一个输入框）、
  点"[重建]"后 `set_top` 的假警告、三元表达式类型不兼容导致**所有 UI 都开不了**、`open` 写 host / 传配置的时机。
- 验证：`--headless --editor` 全项目解析 clean；`--headless` 跑起来无 warning（开局 5 个顶层 UI 都在）。
