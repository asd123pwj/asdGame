### AI的话

- `[url=…]` 的 meta 变成"**事件名 ＋ 冒号 ＋ 一条指令**"，一段链接可挂多条（一行一条）⇒ 箭头既能"按下折叠"又能"悬停出说明"
- **一个事件可以绑多条**（同名项都执行，一条都没命中才冒泡给父级）：可折叠标题"按住拖动 ＋ 按点在哪做事"就是两条独立绑定
- 鼠标左右键事件改名 `Pointer 1 / 2 Hold`：UI 侧统一走逻辑层，物理键状态留着（以后接手柄不用改 UI 配置）
- 宽度上限回到"上限"的语义：只读文本 `宽 = min(内容自然宽, 上限)`（短内容不再撑满）；输入框仍按上限对齐
- 修：浮窗 / 子菜单被 RichTextLabel 与滚动容器裁掉（"开不出来"）；未配上限的文本被按 1px 折行（一行文字变高塔）

### 更新内容

- **富文本链接：meta = 事件名 ＋ 冒号 ＋ 指令**（`Script/UI/Interact/UIInteract_Meta.gd`）
  - 写法：`[url=Pointer 1 Hold:UIInteract.drag(@host, @event)]拖动[/url]`；配置里用 `UIInteract_Meta.as_meta(那一对)` 拼
    （常用那几对在 `QName.UI_event_*`，正文用 `%s` 填）
  - **一段链接可以挂多条**（一行一条）：折叠箭头 = `Pointer 1 Hold:…折叠…` ＋ `Pointer Move:…开 "Tip" 说明…`；
    行间用**换行**分隔（`\v` 仍是"一条指令里接多条子指令"，两种分隔各管一段，别混）
  - 入口只有 `UIInteract.meta_event(@self)`：按本次事件名挑 meta 里对应的那条；对不上就什么都不做
  - **为什么必须读 meta**：元素级 `Pointer Enter` 只知道"指针进了这个元素"，不知道"在哪段链接上"——
    不读它的话移到整行字的空白处也会弹（实测踩过）；`UI_Label` 只接两个 hover 信号维护 `meta_hover`
    （**点击也读它**：点在链接上时它就是那段，不接 `meta_clicked`）
  - **链接不画下划线**：这个版本没有 `font_link_color` 那套主题项，下划线是常量 `underline_alpha` 画的 ⇒ 置 0
    （实测：引擎默认 50）
- **说明浮窗（Tip）的收放规矩也在这一个文件里**
  - 一个元素**同时只留一扇**：悬停到另一段字又开一扇时，先把本元素上一扇收掉
  - 指针不在"有说明的那段字"上就收；**移进浮窗自己身上不算离开**；移出整个元素（`Pointer Exit`）时全收
  - "移进浮窗算不算离开"与子菜单用的是**同一条判据**：`UIInteractBase._in_subtree`（原来两处各写一遍，已合并成一处）
  - `open(..., content="…")` 的正文用 `content_cmd` 读外壳的 content（`@self.parent.config.content`），
    所以**一份 "Tip" 预设能说明任何东西**；`open` 合并完临时配置会 `refresh_tree()` 让子树跟上
- **通用说明浮窗**（`Config/UI/UIPreset_Basic.gd`）：`Tip` 预设 ＋ `tip_events("关闭")` / `tip_events("缩放")`
  - 关闭按钮、缩放手柄"移上去说一句"；**按钮没有链接 ⇒ 走元素事件**（整块都算说明），文本里的链接走 meta
- **一个事件可以绑多条**（`UIBase.on_event`）：同名项**都执行**（按配置顺序），一条都没命中才冒泡给父级
  - 可折叠标题就是两条：`[pointer1_hold, drag(@host, @event)]` ＋ `[pointer1_hold, meta_event(@self)]`
- **折叠标题改造**（`Script/UI/Interact/UIInteract_Fold.gd`）
  - 箭头那段链接的 meta 带着 `QName.UI_event_pointer1_fold_parent`（按下 ⇒ `toggle_fold(@self.parent)` ＋ 对调两套文字 ＋ 刷新）
  - 同一段链接再挂一条悬停说明，**说明文字随状态换**（展开时"点击这里收起这一段"、收起时"点击这里展开这一段"）
  - **删掉 `fold_or_drag`**（"又折叠又拖动"的合成函数）：折叠就写折叠、拖动就写拖动，由"点在哪"挑
- **鼠标左右键事件改名**：`QName.mouseLeft / mouseRight` → 逻辑层 `pointer1_hold` / `pointer2_hold`
  - UI 侧（各配置、`QName.UI_event_pointer1_*`）统一走逻辑层；**物理层 `mouseLeft` / `mouseRight` 保留**
    （`pointer*_hold` 依赖它满足）——以后接手柄只要给逻辑层再添一条来源状态，UI 配置一个字不用改
  - `mouseLeft_press / _tick / _release` 没人用，连同引用它们的注释一起删
- **宽度上限的语义回到"上限"**（`UI_Label._content_size` ＋ 新的 `_plain_width`）
  - 有上限 ⇒ `宽 = min(内容自然宽, 上限)`：自然宽按**去掉 BBCode 的原文**自己量（RichTextLabel 报的是
    "折行后最宽行"，宽没定或已折行时都问不出本来多宽）⇒ 短说明不再撑出一大段空白、超了才折行
  - `UI_Input` 不变：**宽 = 上限**（表单控件同一栏要对齐；与只读文本的差异已写进它的注释）
- **修：浮窗 / 子菜单被裁掉**（"开不出来"）
  - 撤 `UI_Panel` 根控件的 `clip_contents`：它把"挂在面板里、却要画到面板外"的浮窗整个裁没（只剩约 24px 一条边）
  - `UIBase._free_box` 改为**往上找最近一个有叠加层的祖先**：文本的内核 RichTextLabel 自带裁剪、滚动容器也要裁，
    挂在它们下面画不出去；**元素层的父子关系不变**（登记名、`@self.parent` 链、失焦挂载点照旧）
- **修：只读文本的"高塔"空白**
  - 未配上限时不再照抄引擎在"1px 宽"下报的尺寸（那会按"一个字一行"报出 1×N 行，被 `_fit_size` 固化成元素尺寸）；
    改读控件**自身**的最小尺寸（不读 combined——它含我们写回的旧 `custom_minimum_size`，错的高度会粘住）
- **字体来源改成项目内 ttf**（`SysCfg.ui_font_file` ＋ 可选 `ui_font_embolden` 几何加粗）：替换原来的"按名字找系统字体"
- **顺带**：MiniHUD 高度改为随内容（原来固定 220，底下空一截）；说明浮窗正文宽度走 `SysCfg.ui_view_chars`；
  删掉没人用的 meta 消息桥（`Msg.send/listen_ui_meta_*`）与 `UI_Input._text_width`；
  文档与注释里过期的 `"Mouse Left" / "Mouse Right"` 示例统一成 `"Pointer 1 Hold" / "Pointer 2 Hold"`（9 个文件）
- 验证：`--headless --editor` 全项目解析 clean、`--headless` 跑起来无脚本错误；探针逐条实测——
  meta 前缀分流（对不上不执行）、悬停出说明且随状态换、换扇自动关上一扇、移进浮窗不关、
  短说明窗 57×40 / 长说明 416×88 折 3 行、点箭头才折叠；另自动扫过一遍"定义了但全树只出现一次"的函数 = **0 个孤儿**
