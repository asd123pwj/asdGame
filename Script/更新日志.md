# 更新日志

## 0.26.14 UI交互：点击置顶

- 添加了一个点击置顶的交互

### 新增 · 点击置顶（Script/UI/Interact/UIInteract_SetTop.gd）

- 新交互文件 `UIInteract_SetTop.gd`（`extends UIInteractBase` ⇒ 指令名自动是 `UIInteract.set_top`），一个静态入口 `set_top(target)`。
- 提的是**窗口**，不是被点到的那一个元素：沿 `parent` 链爬到最外层那个 UI（挂 UI 根的那个）再 `control.move_to_front()`。直接对元素做会同时踩两个坑：① 同级窗口没被排过 ⇒ 看着"根本没生效"；② 元素在 `VBox` / `PanelContainer` 里时，重排兄弟 = **改布局**，被点的小元素当场跳位置（表现为"子 UI 在面板里乱窜"）。窗口自己挂在 `CanvasLayer` 下（不是容器），重排才是安全的。
- **只需一句 `move_to_front()`**：命中已改成按控件树走（同级倒序 + 孩子优先），与绘制是同一套顺序 ⇒ 不用再维护"登记顺序"（旧版那套要删了再写的 `_bump_tree` 已删）。
- 接线：`PointerDetect.key` 里除"指针移动 / Pointer Enter / Pointer Exit"外的派发都自动调它；`open` 里也调一句（新开的排最前）。HOLD 每帧都派发，所以用 `_front` 记住"最近提的是哪个窗口"去重，不会每帧重排。

### 新增 · 开关列表里的一项（Script/UI/Interact/UIInteract_SwitchValue.gd）

- `UIInteract.switch_value <目标> <键> <值>`：`config[键]` 列表里**已经有（按内容比）就删掉、没有就追加**；值可以引变量（如 `$QName.UI_event_mouseLeft_drag`）。不是列表就警告不动。
- 与 `swap_config` 的分工：`swap_config` 整份对调（开关按钮连行为带文案一起换）；`switch_value` 只加减**一项**——"给宿主加/减一条绑定"不必为此在宿主预设里预先摆两套 `events` 并手工保持同步。
- 菜单"启用/移除拖拽"因此变成一句：`UIInteract.switch_value $parent.parent.parent.parent events $QName.UI_event_mouseLeft_drag`（另一句只换自己的文案）；`UIPreset_Basic` 的面板与 `UIPreset_Keyboard` 里那些 `events_2` 都删了。
- 新增 `QName.UI_event_mouseLeft_drag`（= `[QName.mouseLeft, "UIInteract.drag $self $event"]`）：常用的那套绑定只写一处，配置里填空即可。
- `config` 是"数据"，`events` 这类列表在派发时（`UIBase.on_event`）才读 ⇒ 改完立刻生效；`content` 这种要镜像到运行时字段的键不在本函数职责内（那是 `swap_config` 顺手做的事）。

### 通用化 · 状态名去掉 `| Hold`（Config/QuickName.gd）

- `QName.mouseLeft_hold`（`"Mouse Left | Hold"`）→ `mouseLeft`（`"Mouse Left"`）、`mouseLeft_hold_tick` → `mouseLeft_tick`、`mouseRight_hold` → `mouseRight`；鼠标键只留 `hold` 一个状态（`press` / `release` 那两条注释掉了），Submit 由 PRESS 改 HOLD。
- 读法：**`"Mouse Left"` 就是"按住"**（HOLD 每帧发，按住期间一直满足）；要"按下的那一下"才写 `"Mouse Left | Press"`。
- 状态层的快捷指令名顺带改成状态名本身（`[QName.mouseLeft, QName.mouseLeft, "PointerDetect.key \"Mouse Left\""]`）——第一个参数本来就是"给排版用的描述"，现在与事件名合一，少一层命名。
- 全项目配置与文档里的 `"Mouse Left | Hold"` 一并替换（`UIPreset_Basic` / `UIPreset_Keyboard` / `UIPreset_Menu` / `Auto.md` / `UI.md`）。

### 修正 · 失焦关闭（UIInteract_OpenClose.gd）

- 候选 `_blur_uis` 从"只记不删"改成 **open 登记、close 摘掉**：关过再开自动回来，列表也始终只装着"当前真的在开着的那几个"。
- 删掉 `has_blur_ui()`：`PointerDetect.key` 里就两行（`update_targets()` 刷新命中 → `close_blur_ui(hover)`），那层"先判一下有没有"省不了什么，还多一个状态。
- **尺寸为 0 的先不判**：开与判在同一次调用里（先派发事件 → 事件里 open 菜单 → 紧接着判失焦），而这一帧布局还没跑、`get_global_rect()` 是退化矩形（实测高 0，下一帧才 62）⇒ 直接跳过这一条，否则刚开出来的菜单会被自己这一帧的判定关掉（"第一次能开、关掉后再也开不了"）。
- 边遍历边 `close` 会改到 `_blur_uis`（close 里要摘候选）⇒ 先收集、再统一关。

### 修正 · UI 根层号（UiSystem.gd）

- `UiSys.ROOT_LAYER = 100`：地图每个子层用自己的 `CanvasLayer.layer`（世界层 0 = 0~5，以后加世界层还会更大），UI 根取默认值 1 会被地图盖住 ⇒ 固定成一个明显更大的值，给以后加地图层留富余。

### 修正 · 指针命中：沿控件树走（PointerDetect.gd / UIBase.gd）

- 从"遍历 `uis` 倒序取第一个命中"改成**沿 Godot 控件树走**：UI 根的孩子（窗口）倒序 → 每层 Control 也倒序（同级后画的在上面）→ 进一个 Control 先问它的孩子（孩子画在父之上），都不中才算它自己 ⇒ **命中顺序 ≡ 绘制顺序**，`uis` 退化成"名字 → 实例"的字典（顺序无含义）。
- 控件 → UIBase 的反查：`UIBase.build()` 把"我自己"挂在 `control` 的 meta 上（`UIBase.META_UI = "ui_base"`），走到没挂 meta 的内部控件（容器的 `PanelContainer` / `VBox`、文本内部的 `Label`）就沿用外层那个元素。
- **不做"祖先矩形剪枝"**：自由定位元素（叠加层里那些）本来就画在父矩形之外，菜单还会伸出宿主 ⇒ 按父矩形剪掉子树 = 那些地方点不到（实测踩过：菜单被叠加层剪掉，点在菜单上却命中面板的文本）。
- 修掉刷屏的错误：`get_meta(键, 默认值)` 在键不存在时**仍会打错误日志**（"does not have any 'meta' values with the key 'ui_base'"），而命中要沿树问每个内部控件 ⇒ 改成先 `has_meta` 再取。

### 改动 · 输入：帧末清零改为 deferred（InputSystem.gd）

- `end_frame()` 删掉，`Sys._process` 末尾那句也删了；改为 `_process` 里 `_clear_mouse_delta.call_deferred()`——deferred 队列在**本帧所有 `_process` 跑完之后**才 flush，所以晚于它的消费方（`TimeSys._process` 的 Tick → 拖拽/缩放）仍读得到本帧位移。
- 实测：`_process` 之后 `mouse_delta` 仍是 `(7,0)`（没被提前清，这正是拖拽还能读到它的原因）；一帧之后 `(0,0)`。

### 改动 · 配置目录与 RESET 挪到 SysCfg 常量（Config/SystemConfig.gd / ConfigBase.gd）

- `USER_CONFIG_DIR` / `SYS_CONFIG_DIR` / `RESET` 从 `Sys`（SystemManager）的静态变量改成 `SysCfg` 的常量：唯一使用者本来就在那边（ConfigBase / PresetRegister），常量也不会出现"静态变量取到空值"这类时序问题。全项目 `Sys.RESET` / `Sys.USER_CONFIG_DIR` / `Sys.SYS_CONFIG_DIR` 一并替换。
- 用户配置目录：`user://Config/` → `res://tmp/Config/`（RESET=true 时每次启动重新生成，属于**可随时删的产物**；放项目内方便对照代码看，又不会把 json 堆在根目录，`tmp/` 已在 .gitignore 里）。
- `ConfigBase` 加兜底：`_init` 先校验目录以 `res://` / `user://` 开头（不合法就报错跳过——否则拼出来的是相对路径，会写到项目根目录，就是以前"项目根莫名多出一堆 json"那个坑），并补齐结尾的 `/`；`save()` 建目录改用"这份文件所在的那一级"，不再依赖配置目录常量。

### 改动 · AutoSys 进 _process（AutoSystem.gd）

- `update()` → `_process(delta)`（与其它系统一个形状），由 `Sys._process` 直接调；`Archetype_System` 里那条 Tick 快捷 `AutoSys.update` 删掉。

## 0.26.13 UI交互：缩放

- 修正了一些交互错误，把不同交互用单独的文件存放，不会那么乱了
- 增加了一次性的消息接收器，在接收到消息后自我销毁
- 增加了AutoSys，可以添加长期任务，在条件不满足时销毁任务
  - 使用上面的一次性消息接收器，添加一个一次性的监听器，这个监听器用于监听状态不满足，不满足则会销毁任务
- 增加了缩放交互，长按缩放按钮，移动鼠标，UI会等比例缩放
  - 用到了上面的AutoSys，长按状态触发时，会将缩放函数提交到上面的AutoSys，即松开按键后结束交互。

### 新增 · 状态驱动执行器（Script/Auto/）

- 一句话：**"某角色某状态满足期间，每帧跑一个函数"**。一条登记 = `[角色, 状态名, Callable]`，每帧 `AutoSys.update()` 过一遍：状态还满足就调它，不满足了直接删掉这条登记 —— 所以调用方**不用写"松开"那一半**。
- 接口 `AutoSys.run_until_unsatisfied(char_, status_name, callback)`；同一个"角色 + 状态 + 回调"只登记一次（重复调用无副作用）。
- 为什么需要：按住类交互（拖动、等比缩放）**指针必然离开元素**——缩放时手柄会被指针甩在身后，靠 hover 派发的事件中途就断了；挂在状态上与"指针在哪"无关。
- 接线：`Sys.autoSys`（SystemManager 新增）+ 状态层一条 Tick 快捷 `AutoSys.update`（`Archetype_System` 的「指针交互」组）。
- 交互侧一律写成**一对**（登记入口 + 每帧执行），配置里只写登记入口：
  - `UIInteract.drag $parent $event` → `dragging`：把本帧位移（`InputSys.mouse_delta`）加到 `control.position`；指针移出 UI 也照拖，指针不动时位移为 0 不会漂。
  - `UIInteract.rescale $parent $event` → `rescaling`：**增量式**——`scale *= |指针-面板左上角| / |上帧指针-面板左上角|`，所以按下瞬间不跳变、不需要记抓手、也不需要"松开"回调（缩放中心是左上角；垂直于对角线的位移在数学上跟不了，等比只有一个自由度）。上下限与保护值在 `SysCfg`：`resize_min_scale` / `resize_max_scale` / `rescale_epsilon`。
- 顺带把这轮之前那套"捕获式"缩放删掉了：`UIInteract.resize_begin/resize_end`（五条指令）→ 现在缩放手柄的配置里只剩一条 `rescale`。

### 新增 · 消息系统的一次性接收器（once）

- `MessageNode` 的接收器从两个变**四个**：普通 / **一次性** / identity / **一次性 identity**；`send` 按这个顺序过四个列表，一次性接收器**发完即自删**（返回的 id 失去意义，但 `unlisten` 仍删得掉）。
- `MessageBus` 加 `once` 开关与 `MsgBus.unlisten`（提前取消也能删干净），`MessageHub` 的各 `listen_*` 都支持一次性；`rebind_identity` 连一次性身份接收器一起搬。
- 用途：像"监听某状态不满足"这种**只关心一次**的事件，收完自退订，调用方不用管生命周期（这正是拖拽/缩放收尾那类需求的省事写法）。

### 通用化 · 状态名/事件名统一走 QName（Config/QuickName.gd）

- 新增 `QName`：状态名、事件名、hover 内置事件（`pointer_enter` / `pointer_exit`）都不再写裸字符串——改名只改一处，也避免"配置里写错一个字就静默失效"。
- **一个鼠标键拆成三个状态**：`press` / `hold` / `release`（右键同理，用到的是 `hold`）。每帧 HOLD 仍由 `InputSys._process` 发，所以组合状态（如 `Mouse Left | Hold | Tick`）照旧被逐帧驱动。
- `Archetype_System` 的 statuses / shortcuts 全量替换为 `QName.*`（含方向键、Submit、时间周期那几个）。

### 通用化 · 交互按"一个交互一个文件"拆开（Script/UI/Interact/）

- `UIInteractBase.gd` = **基类**：指令前缀声明一次（`const CMD_HOST := "UIInteract"`）+ 组内共用的 target 校验 `_as_ui`；六个交互文件各自 `extends UIInteractBase`：`OpenClose` / `Drag` / `Rescale` / `Fade` / `Content` / `SwapConfig`。
- 指令系统新增**命令前缀组**：`CmdSys._cmd_host` 沿继承链找 `CMD_HOST`，于是这些文件的静态方法全都注册成 `UIInteract.xxx` —— **拆文件对外看不出区别**。加一个交互 = 加一个 `UIInteract_Xxx.gd`（`extends UIInteractBase` + 写静态方法），指令名自动是 `UIInteract.xxx`，不需要登记到任何表里。
- 原则落地：**一个函数的子函数跟它在同一个文件**——登记入口与它每帧干的活（`drag`+`dragging`、`rescale`+`rescaling`）同文件；只有"开/关"共用的取件（`_child_ui`）才留在开/关文件里。

### 修正 · 开关交互（open / close）

- `open_ui` / `close_ui` 合并成 `UIInteract.open` / `UIInteract.close`：`close(target)` 关 target 自己；给了第二个参数就关"挂在 target 下的那个预设 UI"（菜单项深处手上只有面板引用 + 一个预设名，要关的是挂在它下面的子 UI，不是面板自己）。一律 `hide()` + 广播，实例留着复用；查不到就什么都不做（幂等）。
- **开启不再是"转发壳"**：`open` 里就是实现（按"挂载点 + 预设名"复用查找 → 没有才现建 → 按自己的 `open_at` 摆位并显示），并返回开出来的实例。
- 原来在 `UiSys` 的开启子方法（`open_ui` / `_build_open` / `_place`）与它的取件（`get_child_ui` → `_child_ui`）全部搬到 `UIInteract_OpenClose.gd`；`UiSys` 现在只剩"登记表 + 登记名规则 + 登记 + 取件"。`register_child` 改用 `_reg_name`（登记名规则从此只有一处写法）；`find_name` 里遗留的调试 `print` 删掉。
- **失焦关闭也搬到那儿**：候选不再是"每次按键扫整张登记表"，而是 open 时随手记下的**小列表** `_blur_uis`（只有开出来的 UI 才可能配 `close_on_blur`；只记不删——关掉只是 hide，实例还会被 open 复用，而且判定时正在遍历它）。`has_blur_ui` / `close_blur_ui` / `_is_inside` 一起搬，`PointerDetect.key` 的调用点跟着改。
- 占位符解析同步归位：`UIInteract.resolve_cmd` → `UIBase._resolve_cmd`（`on_event` 的私有助手，不挂在指令面上），并支持 **`$event`**（事件名 = 状态名，拖动就不必再抄一遍状态名）；`UIBase.add_event` 删掉——加/减交互一律走"两套配置 + `swap_config`"或"开/关一个预设 UI"。

### 修正 · 菜单的开关式菜单项

- `EnableDrag` 补上 `events_2`（与 `CloseToggle` 同形状：两套 `events` + 两套 `content`，点一下"做事 + 换一套"）。真正被对调的是**宿主的两套 events**（一套含拖动绑定、一套不含），开关状态存在宿主身上；两套命令内容一样是因为"对调"是自反操作，点第二次自然换回来。
- `UIBase.swap_config` 加保护：两套配置**没有成套写**时什么都不做 + 警告 —— 否则会把写了的那套换成 `null`，等于"点一下菜单项，宿主的交互全没了"（这种坑很难查）。

### 修正 · 指令系统

- `_build_args` 的参数优先级明确为「命名参数 > 位置参数 > **方法默认值** > 类型零值」：`UIInteract.close $parent`（只给一个参数）会吃到 `preset_name = ""` 的默认值。（先前 `fade_to` 上"callv 不走默认值"的注释是错的，已改正。）
- `_lazy_load` 改为收拢**同一前缀的所有文件**（类名等于前缀的 + `CMD_HOST` 匹配的），所以懒注册模式下也能拆文件。

### 通用化 · 背景九宫格边距改为逐图指定

- `UIBase` 的 `BG_SLICE` / `BACKGROUND_SLOTS` 常量删掉：边距取 `config["background_slice"]`（不写 = 0 = 整张拉伸，每张图的圆角不一样，所以必须逐图给），找 stylebox 槽的顺序挪到 `SysCfg.ui_background_slots`。

### 验证

- 探针实测（跑完即删）：
  - 指令注册：`UIInteract.` 前缀下 13 条（`open` / `close` / `drag` / `dragging` / `rescale` / `rescaling` / `fade_to` / `set_content` / `swap_config` + 4 个私有助手）；
  - `open` 开两次复用同一实例；`close <面板> CloseButton` 只关子 UI（面板仍可见），`close <面板>` 关自己（走默认参数），重开后仍是同一实例；

### 注意
