# 更新日志

## 0.26.11 添加/移除关闭按钮

- 添加按钮很简单，
  - 用`UIInteract.open_ui $parent.parent.parent.parent CloseButton $parent.parent.parent.parent`，
  - 两个`$parent.parent.parent.parent`分别用于指定父UI，与指定影响UI
  - 之所以这么长，是因为`MiniHUD/Menu/Edit/MenuEdit/CloseToggle`，即`CloseToggle`要给`MiniHUD`添加关闭按钮

- 这个`CloseButton `也很简单
  - `"events": [["Mouse Left", "UIInteract.close $parent"]]`鼠标点击时关闭父UI

- 移除按钮也很简单
  - `UIInteract.close_ui $parent.parent.parent.parent CloseButton`

- 切换状态也很简单
  - `UIInteract.swap_config $self events events_2`，切换交互事件
  - 这个函数的作用就是交换两个属性内容，没什么特别
  - 我原本想做设置属性内容的，但感觉很奇怪，那样

- 结合起来就是，打开菜单，点击`添加关闭按钮`后，
  - 会添加一个`关闭按钮`，
  - 且`添加关闭按钮`变为`移除关闭按钮`
  - `添加按钮`的事件变为`移除按钮`的事件
  - 也就是一次点击触发三条命令

- 而这个可切换的UI，仍然是最朴素的文本UI。
  - 我第一次想做的是现在这种可切换的，但我突然想起来有可选框UI，理论上Godot也有，但AI大人并没有直接用Godot的可选框UI
  - 没想到AI大人这么厉害，遵循了我之前尽量用原始UI的做法，没有引入新的`Control`，而是搞了个`UI_CheckBox`，但实际内容就是这种切换数据的
  - 然后我给优化了一下，让他直接改为一个交换函数，现在这个效果非常好，可以做无穷多的切换事件


```python
["MenuEdit", "UI_Panel", {
    "size": [170, 0],
    "free": true,
    "open_at": Enums.OpenAt.ANCHOR_TOP_RIGHT,  # 开在触发它的那个菜单项的右上角顶点
    "close_on_blur": true,
    "children": [
        # 关闭按钮：**开关式按钮**（普通 Label，不需要专门的开关元素）——同一个元素上写两套配置，
        # 点一下"做事 + 换一套配置"；一条事件串可以写多条命令（\v 分隔，见 CmdSys.execute）。
        # "加/减关闭按钮"就是开/关一个普通 UI 预设（CloseButton，见 UIPreset_Basic.gd），
        # 所以这里没有任何专门函数：第一条命令就是普通的 open_ui / close_ui。
        ["CloseToggle", "UI_Label", {
            "content": "启用关闭按钮",
            "content_2": "移除关闭按钮",
            "events": [
                ["Mouse Left", "UIInteract.open_ui $parent.parent.parent.parent CloseButton $parent.parent.parent.parent"
                    + "\vUIInteract.swap_config $self events events_2"
                    + "\vUIInteract.swap_config $self content content_2"],
            ],
            "events_2": [
                ["Mouse Left", "UIInteract.close_ui $parent.parent.parent.parent CloseButton"
                    + "\vUIInteract.swap_config $self events events_2"
                    + "\vUIInteract.swap_config $self content content_2"],
            ],
        }],
    ],
}],
["CloseButton", "UI_Label", {
    "content": "X",
    "size": [20, 20],
    "free": true,                                  # 自由定位：挂到宿主叠加层，位置不被父级布局覆盖
    "open_at": Enums.OpenAt.ANCHOR_TOP_RIGHT_IN,   # 开在锚点（宿主自己）内部的右上角
    # 点它就关掉它挂着的那个 UI（$parent = 它的挂载点 = 宿主）
    "events": [["Mouse Left", "UIInteract.close $parent"]],
}],
```

### 新增 · 开关式按钮 = "配置对调"，不再有专门的开关元素

- `UIBase.swap_config(键A, 键B)`：对调 `config` 里两项的值（如 `events`↔`events_2`、`content`↔`content_2`），
  换完**同步镜像**（`_sync_from_config`：content / visible）再 `refresh()`——元素显示读的是运行时字段、
  不是每次都去读 config，不同步的话界面不会跟着变（这是这类用法最容易踩的坑）。
- `UIInteract.swap_config $self 键A 键B`：指令入口，只转发（与 `set_content` 同一套分工）。
- 于是普通 `UI_Label` / `UI_Image` 就能当开关：**两套配置同时写在元素上**，点击时"做事 + 换一套"，
  下次点击自然走另一套。`events_2` 不需要任何代码支持——`on_event` 每次都读 `config["events"]`。
- 一条事件串可以写多条命令，用 `\v` 分隔（`CmdSys.execute` 就是按它 split 的）：

  ```gdscript
  "Mouse Left" → UIInteract.open_ui <宿主> CloseButton <宿主>
                   \v UIInteract.swap_config $self events events_2
                   \v UIInteract.swap_config $self content content_2
  ```

- 期间做过又撤掉的：`UI_CheckBox` 原子元素（勾选框）。"开关"是一种**配置用法**，不是一种元素，已删除。

### 统一 · 关闭按钮 = 普通预设，"加/减"就是"开/关"

- 删掉 `UIInteract.add_close_button` / `remove_close_button`（成对的专门函数 = 同一需求两套策略）。
- 新增预设 `CloseButton`（`Config/UI/UIPreset_Basic.gd`）：`content "X"`、`size [20, 20]`、`free`，
  点它 `UIInteract.close $parent`（`$parent` = 它的挂载点 = 宿主）。
- 加 = `open_ui <宿主> CloseButton <宿主>`；减 = `close_ui <宿主> CloseButton`。
- 新增 `UiSys.get_child_ui(mount, preset_name)`（按"挂载点 + 预设名"取，= `open_ui` 复用那把钥匙的公开形式）
  与 `UIInteract.close_ui(target, preset_name)`（与 `open_ui` 成对，没开过就什么都不做，沿用统一的隐藏语义）。
- 新增 `Enums.OpenAt.ANCHOR_TOP_RIGHT_IN`：开在锚点**内部**右上角（按自己宽度内缩）；
  `ANCHOR_TOP_RIGHT` 是压在右上角顶点（落在面板外），给面板加按钮要用 IN 版。
  **新枚举值一律追加在末尾**：存盘的 json 记的是整数，插在中间会让旧值串位。
- 顺手删掉的死代码：`UIBase.remove_child_element`、`UiSys.unregister_tree`——它们唯一的调用方就是
  `remove_close_button`，而"减"现在走隐藏语义（实例保留、重开走 `open_ui`，重复"启用"不重复加），这条路没人用。

### 统一 · 登记名只剩一条规则（原 `=>` 全部改成 `/`）

- `_reg_name`：无挂载点 → 预设名（`MiniHUD`）；有挂载点 → `挂载点的登记名/名字`（`MiniHUD/Menu/Edit/MenuEdit`）。
- **"开出来的 UI"与"配置里的子元素"共用这条规则**（子 UI 的名字就是它的预设名），
  于是登记表就是一整棵用 `/` 连接的树，看名字就知道挂在谁下面。
- 随之删掉 `register_child` / `add_child_element` 的 `reg_name` 参数（原来"UI 之间用 `=>`、内部子元素用 `/`"的双轨取消）。
- 实测登记表：

  ```
  MiniHUD | MiniHUD/Title | MiniHUD/Close | MiniHUD/Info
  MiniHUD/Menu | MiniHUD/Menu/Close | MiniHUD/Menu/Edit
  MiniHUD/Menu/Edit/MenuEdit | MiniHUD/Menu/Edit/MenuEdit/CloseToggle
  MiniHUD/Menu/Edit/MenuEdit/EnableDrag | MiniHUD/Menu/Edit/MenuEdit/Advanced
  MiniHUD/CloseButton
  ```

- 注意同一挂载点下不要重名（会互相覆盖：子 UI 的名字就是它的预设名）。

### 现状 · 仍然成立的两条结构规则（前一轮结论，继续以此为准）

- **挂载规则**：有 `anchor`（触发它的那个元素）→ 挂在 anchor 下；否则挂在 `host` 下；都没有 → UI 根（独立 UI）。
  于是菜单链是一棵单链子树 `MiniHUD → Menu → Edit(菜单项) → MenuEdit → …` ⇒ 关父级整条链一起隐藏；
  失焦判定 `UiSys._is_inside`（沿 parent 链）能认出"指针在我这条链上"，**点子菜单不会误关父菜单**。
- **链每深一层，到宿主就多一级 `$parent`**：`Menu` 的项用 2 级、`MenuEdit` 的项用 4 级。级数写多/写少只
  `push_warning` 并用可达的最高级替代（**写错不一定报错**，注意看输出）。

### 现状 · 指令与预设清单（对照用）

- `UIInteract`：`open_ui` / `close` / `close_ui` / `drag` / `fade_to` / `set_content` / `swap_config` / `enable_drag`。
- 预设：`MiniHUD`、`CloseButton`（UIPreset_Basic）；`Menu`、`MenuEdit`、`MenuEmpty`（UIPreset_Menu）。
- 原子元素：`UI_Panel` / `UI_Label` / `UI_Image` / `UI_Scroll`。

### 验证

- 临时探针（跑完已删）实测：开关式按钮点一次 → 开 `CloseButton` + `events`/`content` 对调 + 文本变"移除关闭按钮"；
  再点一次 → 隐藏它 + 换回；登记表全为 `/`；`open_ui` 复用与 `get_child_ui` 取值都命中。
- 探针删掉后复跑（`--headless --quit-after`）无脚本报错；`UiSystem.gd` / `UIBase.gd` / `UIInteract.gd`
  等改动文件 lint 干净（`PointerDetect` 那 3 条 `shape` 警告、`test.gd:84` 的 `Variant.keys()` 是既有的）。

### 注意

- 旧 json 仍是老问题：`Archetype_System.json` / `UIPreset_Basic.json` / `UIPreset_Menu.json` 会覆盖代码里的 `values`；
  当前 `Sys.RESET = true`（每次启动重新写盘、不读旧 json），不需要手动清理。
- 加"开关/状态"这类东西时的固定套路：**两套配置写在同一个元素上 + `swap_config` 对调**，
  不要再为它新增元素类或成对的专门函数。
