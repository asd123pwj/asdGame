## 0.26.25 角色交互查看UI 

- 能实时查看角色交互相关的值
  - 除了因为我还没想实现修改而不能修改，其他都不错
- 实现了一个交互的`any`消息
- 实现了一个最后相关交互的时间记录，因为一些交互仅执行一帧，或者说，所有交互都是仅执行一帧
- 之后再把其他的时间也记录上，因为状态也有这样仅一帧的

### 更新内容

- **新增：角色交互一览**（`Config/UI/UIPreset_Interaction.gd` + `Script/UI/UI/UI_Interaction.gd`）
  - 打开：`UIInteract.open(preset_name="Interaction")`，默认看 `char_A`（换人写 `content_cmd="@Char/兔子"`，再点 `[刷新]`）
  - **一条交互 = 一段**（默认收起，标题是摘要 `名字（实现类 ｜ 依赖：状态名 ✔ ｜ 最近执行 16:48:13.697 ×3）`），展开看四类信息：
    `interaction_name` → 实现类（类名写错时红字报"**没建出来**"）／`dependence_status` → 依赖状态 + 现在满不满足
    （带 `@identity` 的连"解析到了谁"一起写）／**流水三行**／`config` → 一行一个键（值用 `_brief` 截断）
  - 实时：每条交互订**它依赖的那个状态**（`satisfied` / `unsatisfied`——与 `InteractionPreset.listen` 触发时看的是同一个节点）
    ⇒ 收到只重铺那一段，✔/✘ 当场变；另订"任意交互"通配（见下）
- **新增 `ANY_INTERACTION` 通配**（`MessageHub`）：`send_interaction_any_changed` / `listen_interaction_any_changed`
  - 节点 `["CHAR", 角色, "ANY_INTERACTION", "ANY", "changed"]`、payload `[交互名, 动作]`（动作 = `add` / `remove` / `act`）；
    三个具体的 `send_interaction_*` 各顺手发一条 ⇒ "不关心是哪条交互"的订阅**订一条就够**
    （具体消息按交互名分节点，运行期新加的交互本来收不到）
- **交互流水**（`Interactions.history` + `record(name, action)`）
  - 三个动作都记：`add` / `remove`（`add_interaction` / `remove_interaction`）+ `act`
    （`InteractionPreset.listen` 的触发函数里，**先记再广播**——接收方要读到刚记下的这一笔）
  - 每笔两份时间：`clock` = **现实墙上时钟**（`16:48:13.697`——引擎只给到秒，毫秒是自己补的，一秒触发好几次得靠它分先后）、
    `text` = **游戏时间**（`元年正月初一 子时`；`TimeFormat.now_text()` **现算**，不依赖 `update()` 跑没跑过）；触发另记 `act_count`
  - **移除也留档**：交互从 `interactions` 里删了，那一笔仍留着（不然"刚删了什么"完全查不到）；再加回来接着算
  - 一览里：标题上"最近执行 … ×N"（收起也看得见）+ 展开三行 `加装 / 移除 / 执行`
- **修：重铺把展开的段收回去**（`UI_Attr` / `UI_Interaction`）
  - 两处都会整块重铺（buff 增删、交互增删走通配），而重铺 = 按"默认收起"重建 ⇒ 用户展开的段被收回，标题箭头还和实际状态不一致
  - 做法：重铺前把"哪几段展开着"记进 `_open_names`（各自覆写 `reload`），`_fill` 建段时**一次建对**
    （`collapsed` 与 `title_item` 的箭头同时按它来），不再"先按收起建、再展回来"——那样箭头会与实际状态不一致
  - 交互的**触发（act）不再整块重铺**：只**就地重铺那一段**（保留展开态）——标题与流水行一起新；
    整块重铺只留给"成员真的变了"（增 / 删）
- **顺带**：`ui_test` 多开一个交互一览；`UI.md`（一览类元素那份清单 + `UI_View` 管的事）、`Interaction.md`（集合多了 `history`）
- 验证：探针实测——依赖满足 / 解除只重铺那一段且 ✔/✘ 当场变；**触发后仍展开**、标题多出 `最近执行 … ×3`；
  删 / 加**别的**交互（整块重铺）时展开态与 `▾` 箭头都保住；流水读到 `clock` / `text` / `act_count`，
  收起时触发过、展开后行也是新的；`--headless --editor` 全项目解析 clean、`--headless` 跑起来无脚本错误

  因为"重开一个已存在的 UI"是**复用 + 显示、不发消息**，只靠 `listen_ui_close` 那种消息盖不到这一半。
- 验证：`--headless --editor` 全项目解析 clean；`--headless` 跑起来无 warning。
  探针实测：SYS 16 个状态 / 开着 32 条订阅 ⇄ 关掉 0 条、重开 32 条；收起段收到 satisfied 时标题当场变而**位次不变**；
  字号 没配→16、配 8→16、配 28→28；`content_cmd` 改走 config 后照样生效。

## 0.26.20 编辑器UI

- 这次写出来的能用，但是代码我不是很满意，感觉通用性有点差
- 实现了一个编辑器UI，能根据数据类型自动扩展编辑项
  - 因为暂时还不确定最终版本，能用就先这样
- 指令系统
  - 增加对字典的支持
  - 当方法参数有`config`时，会将传入的参数中，与函数支持参数不符的部分，视为`config`的键，即简化`config`传参流程
  - 现在`self`, `event`, `host`的前面需要加`@`，减少一些计算量。
- 注册名系统
  - 未来将淘汰`实例ID`，转为注册名，UI的注册名例如`UI/MiniHUD/Title`，使用即`@UI/MiniHUD/Title`，和原先`@实例ID`一致。


- **编辑器只有一种了：`UI_Editor`（自适应）**——把"要看 / 要改的那个东西"铺成可编辑界面，自己按数据类型挑编辑方式：
  字典 ⇒ 一行一键；字典数组 ⇒ 一项一段（**默认收起**，展开才建）；数字 / 真假 / 文本 / 数组 ⇒ 一个合适的控件。
  "编辑哪个东西"由 UI 通用的**查看项**指定（`content_cmd` / `content`；`host.xxx` 是相对写法），不写就是 host 的 config
  ⇒ **右键任意 UI 就能编它**；要编别的东西（另一个 UI、以后某个角色的属性）只是把对象指过去。
  "一行长什么样、用什么控件" = **模板**（`Config/UI/UIPreset_Editor*.gd`），换个模板就是改一处名字（`kinds` / `special`）。
- **查看项有了"指令版本"**：`content_cmd` 优先（显示什么可以随时算出来），`content` 是字面值 / 兜底；
  指令版本生效时字面值存进内部影子键 `_content_static`，撤掉指令版本还能回到它。
- **指令系统三件事**：
  - `@self` / `@host` / `@event` **由指令系统自己解析**（`UIBase` 里那套"扫字符串换占位符"整套删掉）；
  - 注册名加 **`UI/` 根前缀**（`UI/MiniHUD`、`UI/MiniHUD/Menu/Close`），别的系统以后各用自己的根前缀；
  - 支持**字典字面量** `{...}`（可嵌套；参数切分也认 `{}`），以及**「任意配置键」约定**：方法签名里有 `config` 参数时，
    调用里**没对上参数名**的命名参数都进它 ⇒ 打开时顺手改任意一项配置：
    `UIInteract.open(@host, "Editor", @host, host=@host, content_cmd="host.config", size=[300, 200])`。
- **折叠交互变成通用的"按需加载"**：某段声明了 `items` 时**首次展开才建**里面的东西（编辑器每一段都靠它，
  不必再为编辑器写专用的展开函数）；点标题收 / 展那一套片段也从预设挪到折叠交互里（预设只构造自己的 widgets）。
- **注册名系统**（`Script/System/RegSystem.gd`）：注册名 ↔ **实例**（去掉"实例 ID"那一套；要指哪个东西就写名字）。
- **菜单**：编辑器有自己的右键菜单（"编辑这个编辑器 ▸"）；原来"绑定 ▸"（`config["bind"]`）**废弃** ⇒
  菜单编辑 ▸ → **内容对象 ▸** = 开通用编辑器改宿主的 `content_cmd`（不再为"填一个路径"写专门面板）。
- 修掉的问题：编辑器里提交普通文本会**清空**（"文本 → 值"缺了兜底）、相对写法 `host.` 没展开（编辑器只剩一个输入框）、
  点"[重建]"后 `set_top` 的假警告、三元表达式类型不兼容导致**所有 UI 都开不了**、`open` 写 host / 传配置的时机。
- 验证：`--headless --editor` 全项目解析 clean；`--headless` 跑起来无 warning（开局 5 个顶层 UI 都在）。
