## 2026-09-24　指针：点在滚动条上不再命中 UI（拖滚动条不再连带拖窗口）

- **现象**：面板既有"按住可拖"又有滚动条时，**拖滚动条会同时把窗口拖走**。
- **原因**：命中是"沿控件树往外沿用元素"——滚动条是 `ScrollContainer` 的**内部子节点**
  （`get_child_count()` 默认数不到它），它所在的容器没有挂元素，于是命中了**外层那个元素**（面板）。
- **改动**（`PointerDetect`）：进到滚动容器时先判"点是不是落在它的滚动条上"（`_on_scroll_bar`，按矩形），
  落在就置 `_blocked_by_scroll_bar` ⇒ **整次命中查询作废**（返回"没有 UI 目标"）。
  **只让那一层返回 null 不够**：外层元素（面板自己的根 Control）还在上面，照样会被命中。
  滚动条本身照旧归引擎处理（本项目不消费鼠标事件、不 `set_input_as_handled`）⇒ 拖它照常能拖。
- **顺带说明**：点滚动条不会把窗口提到最前（`set_top` 不触发——那一刻"没有 UI 目标"）；
  指针从元素上移到滚动条，对那个元素算一次 `Pointer Exit`（悬停类浮窗会收）。
- **实测**：滚动条正中 / 底端 ⇒ 命中 `无`；正文 / 标题 / 面板空白 ⇒ `Note` / `Title` / `UI/SizeTest`
  （拖动照常）；真实链路 `hover_ui` = `无` / `UI/SizeTest/Title` ✅
- **边界（也实测过）**：滚动条**没显示**时同一点照常命中（`UI/SizeTest/Note`）；滚动条右边界外 0.5px ⇒ 面板
  —— 只挡**真正显示着的**滚动条（判 `bar.visible`）。
- 涉及文件：`Script/Input/PointerDetect.gd`、`Script/Input/Input.md`。

## 2026-09-24　UI：富文本链接（meta）+ 浮窗 + 面板滚动

### 1. 富文本链接：meta 变成"**事件名 + 冒号 + 一条指令**"，入口收成一个 `meta_event`

- **为什么**：以前"点它做什么"和"悬停它做什么"是两条指令（`meta_click` / `meta_hover`），
  而"哪个事件触发"这件事**指令系统本来就知道**（`CommandParser.event_name`），再维护一张
  Click→某事件 的映射表就重复了。
- **怎么做**：`meta` 写成 `事件名:指令`（一行一条，可挂多条），三条事件都指同一个入口
  `UIInteract.meta_event(@self)`——它按**前缀 = 这次的事件名**挑该执行哪条（对不上就什么都不做）。
  配置里用 `UIInteract_Meta.as_meta(绑定对)` 拼这个形状（常用那几对已在 `QName`）。
- **顺带**：`meta` 直接写"开窗的指令"（`UIInteract.open(@self, "Tip", @self, content="…")`），
  原来的 `tip:` 前缀约定删掉——**开 / 关 / 拖都是同一种写法**（meta 里写哪条指令就做哪件事）。
- **浮窗收放**（全在 `UIInteract_Meta`，配置里不再各写一套 close）：同一元素**同时只留一扇**
  （换一扇 ⇒ 自动收上一扇）；指针不在"有说明的那段字"上就收；**指针移进浮窗自己身上不算离开**；
  移出整个元素全收。
- **实测**：`meta_click` 真的发出指令（`mark=clicked`）；悬停开窗、正文 = meta 里那段文字；
  换一段链接正文跟着换；`meta=null`（这行字的非链接部分）什么都不发、窗保持。

### 2. 浮窗宽度：**自由定位的元素自成一体**，不再被宿主面板的 `fit_content` 管

- **现象**：关闭 / 缩放按钮的说明浮窗变成 `17×112` 的**竖条**（文字折成 4 行，控件宽只剩 1px），
  而且**只在把宿主面板拖小过之后**才出现。
- **原因**：浮窗挂在"以面板为准"（`fit_content: false`）的面板里，`UI_Label` 于是也走"宽度听容器"那一支
  ⇒ 报 0 宽、容器给 1px ⇒ 折成一列。浮窗自己是**内容为准**的，二者打架。
- **改动**：`UIBase._in_fixed_panel` 往上爬到**自由定位的元素（`free: true`，浮窗 / 菜单 / 角落图标）就停**，
  以它自己的声明为准（它自己要固定尺寸就自己写 `fit_content: false`）。
- **实测**：面板已在"以面板为准"时，浮窗 = `77×40` / `97×40`、**单行** ✅（改前 `17×112`、4 行）。

### 3. 面板：内容装不下时**在框内滚动**，不再画到面板外

- **需求**：面板尺寸由面板定（`size` 写了数 / 被"改尺寸"手柄拖小）时，高出的内容应该出滚动条。
- **改动**（`UI_Panel`）：`ScrollContainer` **总是建**（原先只在配了 `config["scroll"]` 时才有），
  横向关掉、竖向自动。配套两条：
  - 内容盒 `size_flags_horizontal = EXPAND_FILL`——滚动容器只把子节点排到"它自己的最小尺寸"、
    不负责拉宽，不写这句折行文本会被压成一列（实测 `正文=(1, 1776)`）；
  - `_content_size()` 改问**内容盒**（滚动容器最小尺寸恒为 0，隔着它问 `_panel` 问不出内容多大），
    再与底图（StyleBox）的最小尺寸取大的那个。
- **实测**：320×220 面板 + 144 高正文 ⇒ 无滚动条；正文 432 ⇒ 滚动条出现、可滚 284；
  手柄把面板拖到 100 高 ⇒ 滚动条出现、可滚 116。回归：MiniHUD `320×160` / TestInput `260×124` /
  MetaTest `396×86` 与改前一致。

### 4. 文本元素：不再被"按 1px 折行"坑到（大段空白的根因）

- **现象**：正文一行字变一列高塔（快捷名 `Key J` 报成 `1×120`）、面板里各处出现大段空白，
  且**怎么刷新都不掉**。
- **原因**：RichTextLabel 按**当前宽度**报内容高，刚建出来时宽还是 1px ⇒ 报"1×N 行"；
  而 `_content_size` 读的是 `get_combined_minimum_size()`（含我们自己写回去的旧值）⇒ 错的高度**永远粘住**。
- **改动**（`UI_Label._content_size`）：读控件**自身**的 `get_minimum_size()`；宽度分三档——
  配了上限就用 `min(内容自然宽, 上限)`（`_plain_width` 自己量不折行的宽度）、
  容器已给宽就用这个宽、宽还没定**先按一行报**（等 `resized` → `_refit` 再算）。
  判"宽度听容器"复用 `_width_from_parent()`（`wrap` / 在"以面板为准"的面板里），**不再写两遍**。
- **实测**：`Key J` `1×120` → `480×24`；快捷每条块高 280/400/424 → 一律 `184`；
  MiniHUD 标题 308 → `24`；MiniHUD 面板固定高 220 → `320×0` 随内容。
