## 0.26.16 编辑框UI

- 本来想让AI直接实现高级编辑菜单，但是效果不好，因此逐步实现
- 这次先实现的是输入框编辑与提交
- 把一些交互拆分为了多条指令，例如这次的提交
  - 点击，进入编辑模式
  - 回车，先写值，再停止编辑，再刷新写好的值
  - 下面是代码，还夹杂一些辅助，例如清空自身

```python
"events": [
    [QName.mouseLeft, 'UIInteract.begin_edit $self'],
    [QName.input_submit,
        'Utils.write "$UiSys.get_ui($self.parent.config.bind).config.content" $self.control.text'
        + '\vUtils.write "$self.config.content"' 
        + '\vUIInteract.end_edit $self'    
        + '\v$UiSys.get_ui($self.parent.config.bind).refresh("content")' 
        + '\v$self.refresh("content")'],    
],
```

- 但还有个问题，现在指令系统支持多种形式了，命令行传参哪种，以及代码调函数这种
  - 不太统一，下个版本改一下
- 实现了一个设置值，`Utils.write`，交换值，`Utils.swap`
  - 它们接受的是值的路径，也就是像指令系统一样，还是挺不错的
- 增加了一个移出关闭的交互，用于自动弹出菜单的自动关闭


### 新增 · 输入框与编辑（Config/UI/UIPreset_Test.gd、Script/UI/UI/UI_Input.gd、Script/UI/Interact/UIInteract_Edit.gd、Script/Input/InputSystem.gd、PointerDetect.gd）

- `UI_Input`（LineEdit）：`config["content"]` 是初值（`refresh` 时写进框里，正在编辑时不回写），回车提交 → 派发 `QName.input_submit`。
- **元素里没有任何特判**：不连引擎信号（`text_submitted` / `text_changed` 一律不连），也不写死"点它进编辑"——那就是配置里一条普通事件 `[QName.mouseLeft, 'UIInteract.begin_edit $self']`，换成别的事件触发也行。
- 编辑状态记在 `InputSys.edit_ui`：编辑期间按键**不进状态层**（打的字不会顺手触发 UI 指令 / 状态），**只有回车例外**——翻成项目自己的 `QName.input_submit` 派给正在编辑的那个输入框，于是"回车提交"也走在唯一输入链路上。
- `UIInteract.begin_edit` / `UIInteract.end_edit`（新文件 `Interact/UIInteract_Edit.gd`）+ `InputSys.end_edit()`；"点别处退出编辑"由 `PointerDetect.key` 开头顺手收掉（点回输入框那一下会再进编辑）。
- 提交 = 配置里一串普通命令，按序：写目标的 `config.content` → 清空自己 → `end_edit` → 刷新改过的两个 UI。**顺序不能反**：编辑中的输入框会跳过刷新，先刷就把"清空"漏掉了。
- 测试用：新增 J / K 两个 PRESS 状态与快捷 `UIInteract.toggle --preset_name TestShow / TestInput`（`QName.key_j` / `QName.key_k`）。

### 新增 · `UIInteract.toggle` 与两种"关掉"（Script/UI/Interact/UIInteract_OpenClose.gd）

- `UIInteract.toggle [target] [preset_name]`：**显示着就关、否则开**——绑一个键做"按一下开、再按一下关"（两条独立指令做不到：键状态只在满足变化时给一次）。
- 关闭行为拆成两个 bool，**都在 `open` 那一句给**（不再写进预设：它们取决于"在哪开、为什么开"，写进预设的话每加一层子菜单都得抄一遍、漏一处那个 UI 就永远关不掉）：
  - `close_on_blur`：**点关** —— 有按键派发时判一次，右键菜单那种；
  - `close_on_move`：**移开关** —— 指针一动就判，hover 展开的子菜单挪开就收。
- 两张候选表 `_blur_uis` / `_move_blur_uis`：open 登记、close 摘掉（关过再开能自动回来，表里始终只装"当前真的开着"的那几个）。
- `reset_position()` 换成显式的 `refresh("position")`。

### 新增 · 通用指令 `Utils.write` / `Utils.swap`（Script/Utils/Utils.gd、Script/Command/CommandParser.gd）

- `Utils.write "<路径>" <值>`：通用"按路径写值"，路径语法与取值式完全一致（实例成员 / 字典键 / 列表下标 / 函数头都行），只有两个参数（宿主写在路径里）。**只改数据、不刷新界面**。
- `Utils.swap "<路径A>" "<路径B>"`：对调两条路径上的值 —— 开关式按钮的底座（原来那条 `UIInteract.swap_config` 退役，文件留空壳只是不让 `.uid` / 引用悬空）。
- 路径**用双引号包住**（顶层引号 = 字面字符串）：里面的 `$` 不再被当成取值式，路径原样传给函数；`CommandParser._tokenize` 给"顶层引号内以 `$` 开头"的 token 补转义，`_normalize_path` 补前导 `$`（手写 `\$` 的老写法仍然有效）。
- 配置里指令串外层**统一用单引号**（Godot 与 Python 一样）：里面要写双引号时不必转义成 `\"`，写出来就是指令本身的样子。

### 改动 · 显示内容不再挂成员变量（UIBase / UI_Label / UI_Scroll / UI_Image / UI_Input）

- `UIBase.content` **删除**（中间试过 get/set 属性版，也撤了）：内容就是 `config["content"]` 这一份数据，子类 `refresh(key)` 读它刷到控件上。
- 不做"写 config 自动刷"的理由写在 `UIBase` 注释里：`config` 是 Dictionary、拦不住写入；换成带 `_set/_get` 的对象得把所有读点（`config.get/has/[]`、`duplicate`、`_init(config_)` 参数…）都改一遍，不划算。
- 刷新规矩落定：**改了什么刷什么** ⇒ `$self.refresh("content")`；不传 key 才是"全刷"（当前全刷只多一次 `visible` 判断；`position` 必须显式传 key）。
- 全刷**不做**"old config 比较"（实测结论）：diff 只在"白刷"时省 ~5.7µs/UI，值真变时反而多花一趟遍历，而且要处处同步快照（漏一处就静默不刷），得不偿失。

### 修正 · 带空格的字典键（实测结论，写进 UI.md）

- 路径参数被引号包住时，**引号会保护键里的空格**：写 `Utils.write "$self.config.带 空 格" 值` 可以。
- 取值式那一侧写 `&$self.config.带 空 格`（**不加引号**：`&` 整行原样交给解析器，空格不会被切）。
- `$self.dict."带 空 格"` 这种"给键加引号"的写法**不支持**（引号会变成键名的一部分）；`.get("键")` 也不行（字典不是 Object，取值链的方法分支只认 Object）。
